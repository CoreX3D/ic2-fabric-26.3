# Зелёная книга рецептов

В `0.1.0-alpha.3` исправлено естественное открытие рецептов IC2 в стандартной книге Minecraft. Базовое отображение уже работало, что видно, например, по кранику из досок. Проверка обнаружила 119 обычных рецептов, для которых отсутствовали достижения открытия.

Добавлены 44 открытия рецептов с формой, 69 бесформенных крафтов, три распаковки блоков сырой руды и три переплавки сырого олова, свинца и урана. Среди них — медные пластины, провода, корпуса и часть снаряжения. Рецепт открывается при получении одного из подходящих ингредиентов, по стандартному механизму Minecraft. В существующем мире уже имеющийся материал можно переложить в другую ячейку инвентаря или получить ещё один.

Исправление состоит из 119 новых файлов в `data/ic2/advancement/recipes`. Существующие рецепты и достижения, стоимость крафтов, скрытые специальные рецепты и правила автозаполнения сохранены. Для всех 439 обычных крафтов и переплавок теперь существуют условия открытия. Машинная переработка не является рецептом верстака и не добавляется в его книгу.

Зелёная галочка рядом с поиском включает фильтр доступных крафтов. При его включении книга показывает рецепты, для которых сейчас есть материалы. Для просмотра остальных открытых рецептов фильтр можно выключить.

## Проверка

`scripts/validate_recipe_book_unlocks.py` проверяет покрытие, ссылки на рецепты, ингредиенты и теги. По умолчанию скрипт только читает данные; `--write-missing` создаёт исключительно отсутствующие файлы, без перезаписи существующих.

```powershell
python .\scripts\validate_recipe_book_unlocks.py `
  --minecraft-jar '<vanilla 26.3 client.jar>' `
  --fabric-api-jar '<fabric-api-0.163.0+26.3.jar>' `
  --report .\build\recipe-book-unlocks-static.json
```

Новые серверные тесты проверяют открытие медной пластины, продвинутого аккумуляторного ранца, распаковки и переплавки свинца через обычное изменение инвентаря. Отдельно проверяется сохранение закрытых посторонних, скрытых и машинных рецептов. Все пять новых проверок и полный набор из 447 игровых тестов прошли без ошибок (`build/verification-recipebook-focused.log`, `build/verification-recipebook-alpha3.log`, `build/reports/gametest/results-recipebook-alpha3.xml`).

Русский клиент с модами профиля прошёл проверку (`build/verification-recipebook-client-final.log`, `BUILD SUCCESSFUL`). Обычное получение меди и молота открыло рецепт и передало его клиенту. Настоящие нажатия мыши открыли зелёную книгу, поиск нашёл «Медную пластину», кнопка рецепта заполнила серверную сетку. Нажатие результата создало одну пластину, израсходовало медный слиток и оставило молот с износом 1.

Отчёт и восемь снимков сохранены в `build/client-render-recipebook-alpha3/`. `screenshots/ic2-recipe-book.png` дополнительно просмотрен визуально. Проверка архива и сохранности русского перевода прошла: `build/artifact-audit-recipebook-alpha3.json`, `build/recipebook-localization-audit.json`.

Готовый файл: `ic2-fabric-26.3-0.1.0-alpha.3.jar`, SHA-256 `54cfad503f9ad65d815060d27a2314ececc934141187f11c14ccab738cf9575d`. При обновлении предыдущий JAR сохраняется вне папки `mods`.

## Автозаполнение фигурных рецептов — alpha.5

В `0.1.0-alpha.5` исправлена расстановка ингредиентов через книгу. Штатный `PlaceRecipeHelper` в Minecraft 26.3 узнаёт размеры только у ванильного `ShapedRecipe`. Пользовательский `AdvRecipe` попадал в ветку бесформенных рецептов: три компонента генератора 1×3 размещались горизонтально в первой строке, и результата не было.

Узкий `PlaceRecipeHelperMixin` передаёт размеры только `AdvRecipe` существующей штатной перегрузке размещения. Она сохраняет ширину, высоту, пустые ячейки и обычное центрирование. Шаблоны рецептов, их состав, стоимость и отображение не менялись. Это устраняет общую причину у узких фигурных рецептов IC, а не только у генератора.

Пройдены все 455 игровых тестов и 10 JUnit-проверок (`build/verification-placement-server-alpha5.log`, `build/reports/gametest/results-placement-alpha5.xml`). Восемь новых серверных проверок используют реальные загруженные рецепты и `handlePlacement`, затем забирают результат через обычный клик с расходованием компонентов. Они покрывают генератор 1×3, передатчик частоты 1×2, углеволокно 2×2, топор 2×3 с пустой ячейкой, краник 3×3, центрирование 2×1 и 1×1, сетку инвентаря 2×2 и ванильные контрольные рецепты.

Нативный русский клиент с 11 ранее скопированными модами оптимизации также прошёл проверку (`build/verification-placement-client-alpha5.log`). Обычное получение аккумулятора, корпуса и печи открыло варианты рецепта генератора. Реальные клики по зелёной книге и кнопке найденного рецепта поставили компоненты в центральный столбец — ячейки 1, 4 и 7 при нумерации с нуля. Шесть остальных ячеек остались пустыми. Клик по результату создал один генератор и израсходовал все три компонента. Второй рецепт с железной печью правильно оставался недоступным при имеющихся материалах.

Отчёт и девять снимков сохранены в `build/client-render-placement-alpha5/`. Снимок `screenshots/ic2-generator-recipe-book.png` дополнительно проверен визуально. Тест использовал отдельный временный мир; пользовательские сохранения не открывались.

Проверки архива, состава изменений и русского перевода прошли: `build/artifact-audit-placement-alpha5.json`, `build/placement-artifact-diff-alpha5.json`, `build/placement-localization-audit-alpha5.json`. По сравнению с alpha.4 добавлен один класс mixin, изменены его регистрация и номер версии; все файлы рецептов совпадают.

Текущий файл: `ic2-fabric-26.3-0.1.0-alpha.5.jar`, SHA-256 `d48327183dfa2b719f80488044410ad4af8e470ccb83ca989893365600e33834`.

## Изношенный молот и кусачки — alpha.8

Рецепты железной и свинцовой пластин уже существовали и имели условия открытия. Причина их исчезновения при включённой зелёной галочке была общей: после первого крафта молот получает износ, а штатная проверка `Inventory.isUsableForCrafting` исключает повреждённые предметы. Её используют и подсчёт доступных ингредиентов книги, и поиск предметов для серверного автозаполнения. Поэтому рецепты переставали считаться доступными, хотя молот и слитки находились в инвентаре.

В alpha.8 узкий `InventoryMixin` допускает изношенные кузнечный молот и кусачки, пока у них остаётся хотя бы одно использование. Штатные ограничения для переименованных и зачарованных предметов сохранены, в том числе для этих двух инструментов: некоторые рецепты машин полностью потребляют молот или кусачки. Другие предметы продолжают проходить штатную проверку Minecraft. Книга переносит настоящий стек инструмента; в рецептах повторного использования существующий механизм остатка сохраняет его компоненты и увеличивает износ на единицу. На последнем использовании инструмент ломается по прежним правилам. Рецепты, стоимость и условия открытия не менялись.

Полный серверный прогон прошёл с 467 GameTest и 10 JUnit-проверками (`build/verification-crafting-tools-server-alpha8.log`, `build/reports/gametest/results-crafting-tools-alpha8-full.xml`). Пять новых проверок покрывают штатный подсчёт доступных ингредиентов, выбор из инвентаря и реальное автозаполнение/получение результата: железная и свинцовая пластины одним молотом, повторный крафт проводов кусачками, поломка обоих инструментов на последнем использовании. Пользовательские данные молота сохраняются; ванильные повреждённые инструменты и распылители IC не получают нового исключения.

После уточнения ограничений для имени и зачарования повторно прошли все пять проверок инструментов и 10 JUnit-проверок (`build/verification-crafting-tools-final-alpha8.log`). Дополнительные отрицательные сценарии проверяют молот и кусачки без износа и с износом 1: именованные и зачарованные стеки не учитываются фильтром доступных крафтов и не выбираются автозаполнением.

Окончательная сборка также прошла нативную проверку русского клиента с 11 скопированными модами профиля (`build/verification-crafting-tools-final-alpha8.log`, `BUILD SUCCESSFUL`). Реальные клики по зелёной книге с включённым фильтром доступных рецептов последовательно создали медную, железную и свинцовую пластину. Между крафтами обычное закрытие верстака возвращало тот же молот в инвентарь; повторное автозаполнение сохраняло износ, а получение результата увеличивало его 0 → 1 → 2 → 3. Железный и свинцовый рецепты открывались обычным получением соответствующего слитка.

Отчёт и 12 снимков сохранены в `build/client-render-crafting-tools-alpha8/`. Снимки `screenshots/ic2-iron-plate-recipe-book.png` и `screenshots/ic2-lead-plate-recipe-book.png` показывают доступный рецепт, слиток и изношенный молот в сетке, а также готовую пластину в результате. Проверка использовала отдельный временный мир.

Проверки архива, состава изменений и перевода прошли: `build/artifact-audit-crafting-tools-alpha8.json`, `build/crafting-tools-artifact-diff-alpha8.json`, `build/crafting-tools-localization-audit-alpha8.json`. По сравнению с alpha.7 добавлен только класс `InventoryMixin`, его регистрация и номер версии. Все рецепты и графические ресурсы совпадают.

Файл `ic2-fabric-26.3-0.1.0-alpha.8.jar`, SHA-256 `248345b11be7eeb6c226249b032d0b8f9889f01bf8477fe1af0f83c323576e19`, установлен в профиль Modrinth `26.3`. Предыдущая alpha.7 сохранена в `build/profile-backups/`; запись установки — `build/profile-installation.json`.

## Полная проверка книги — alpha.9

Проверены все 789 ресурсов рецептов. Книга теперь охватывает 449 обычных рецептов: 414 крафтов и 35 переплавок. Остальные 336 относятся к машинной переработке. Четыре динамические операции — ремонт конденсаторов и крепление ранца к произвольной броне — не имеют фиксированного результата для штатной книги. Их собственные правила сохранены.

Причина отсутствия нановолоконного шлема — прибор ночного видения: при изготовлении даже пустой прибор получает `Damage=26` при максимуме 27. Это шкала заряда, но Minecraft исключал такой ингредиент как повреждённый. `InventoryMixin` теперь допускает обычные изношенные ингредиенты IC с оставшимся использованием, включая прибор, краники, ключи, распылители, роторы и резиновые ботинки. Защита переименованных и зачарованных предметов, а также правила для изношенных ванильных вещей сохранены. Переносится настоящий стек с зарядом и компонентами; совпадение рецепта, расход и остатки определяет сам рецепт.

В шести рецептах составных урановых/MOX-стержней книга теряла условие `use=0`. Общий `RecipeBookStackRules` исключает неподходящие стержни из подсчёта и выбора для автозаполнения; `StackedItemContentsMixin` охватывает также предметы в сетке. Исправлено сравнение числовых данных: JSON представляет ноль более узким типом NBT, чем счётчик реактора. Числа сравниваются по точному значению без потери точности; строка `"0"`, ненулевой износ и отсутствующий обязательный ключ не принимаются.

По запросу пользователя открыт показ десяти ранее скрытых обычных рецептов: оловянного ведра, светопыли, пороха, ядерного заряда, бронзовых поршня и рельсов, двух вариантов малой железной пыли, факела из латекса и липкого поршня с латексом. Для последнего добавлено открытие; у остальных девяти открытия уже были. Состав, количество результата и стоимость крафтов сохранены.

Окончательный прогон прошёл с **484 GameTest и 10 JUnit-проверками** (`build/verification-all-recipes-alpha9-final.log`, `build/reports/gametest/results-all-recipes-alpha9-final.xml`). Каждый из 414 крафтов выполнен через настоящий подсчёт доступности, автозаполнение и получение результата со сверкой расхода и всех остатков. Все 449 обычных рецептов проверены через получение ингредиентов и реальные условия открытий. Дополнительно выполнены 43 подходящих крафта с изношенными предметами IC. Проверки стержней охватывают все шесть рецептов, смешанный инвентарь и 16 вариантов данных для каждого из четырёх входных типов.

Русский клиент с 11 скопированными модами оптимизации прошёл финальный запуск. Настоящие клики по книге с фильтром доступности создали нановолоконный шлем из пустого прибора, затем из прибора с 100 000 EU. Шлем получил соответственно 0 и 100 000 EU; все шесть ингредиентов израсходованы. Оба случая используют естественное открытие. Отдельная проверка передачи всех 449 рецептов сверяет каждый клиентский дисплей с серверным: ингредиенты, компоненты результата, категорию, форму, рабочую станцию, а для переплавки — топливо, длительность и опыт.

Отчёт и 14 снимков: `build/client-render-all-recipes-alpha9/`. Снимок `ic2-nano-helmet-recipe-book.png` просмотрен визуально. Построчные результаты: `build/all-book-audit/runtime-*.json`; сводка: `build/all-book-audit/summary-alpha9.json`. Архив и перевод проверены в `build/artifact-audit-all-recipes-alpha9.json`, `build/all-recipes-artifact-diff-alpha9.json`, `build/all-recipes-localization-audit-alpha9.json`. Графические ресурсы и переводы совпадают с alpha.8.

Профиль содержит API `0.164.0+26.3`. Его установленный дистрибутив и 44 вложенных модуля использованы побайтно через локальный Maven-репозиторий; скрипт `tools/prepare-profile-fabric-api.py` воспроизводит его без сети. Хеши: `build/all-book-audit/profile-api-local-repo.json`. Два отсутствующих в пользовательском дистрибутиве тестовых API для 26.3 подключены из кэша только к тестовым исходникам. Производственная сборка использует API профиля. Пользовательские сохранения не открывались.
